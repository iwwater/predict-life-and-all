# 情境化多法会审平台：完整新版开发方案

## 一、产品最终定位

本项目不做普通的“输入生辰八字，生成一篇 AI 命理文章”，也不做简单的“十二种术法结果拼接”。

产品定位确定为：

> **以具体事情为中心，结合人、事、时、地、境和现实条件，进行多法综合会审。**

核心公式：

```text
综合判断
=
个人命盘
+ 当前事情
+ 时间阶段
+ 所在地点
+ 空间环境
+ 现实约束
+ 多法交叉验证
```

产品对外表达可以使用：

> **算人，更算事；看命，也看时、地、境。**

或者：

> **别人解一张盘，我们判断一件事。**

# 二、相对竞品的核心优势

## 1. 从“命盘解读”升级为“事情判断”

常见产品流程：

```text
填写出生信息
→ 排八字
→ AI 生成性格、事业、感情文章
```

我们的流程：

```text
用户提出一件具体事情
→ 补充极少量关键条件
→ 读取个人命盘
→ 分析当前时间和环境
→ 多法分别提供证据
→ 解释共识与分歧
→ 输出针对这件事的结论
```

例如用户问：

> 我是否应该接受这份新工作？

报告不能只说“你的八字适合变化”，而要分析：

* 个人长期职业结构是否适合；
* 当前流年是否支持变化；
* 这份具体工作的条件；
* 是否需要换城市；
* 当前家庭与财务约束；
* 短期起卦信号；
* 空间和方位是否构成辅助影响。

最终输出：

> 长期适合职业变化，但当前这份机会的稳定性不足。建议先确认正式合同和试用期条件，不宜在口头承诺阶段离职。

## 2. 少追问，不做长问卷

默认不追问，必要时只补充一个问题，最多两个。

追问必须满足：

* 直接影响结论；
* 可以用按钮选择；
* 不要求用户输入长篇背景；
* 不询问系统已经知道的信息。

例如换工作只问：

```text
是否已有明确 offer？
已有 / 还没有
```

感情只问：

```text
你们目前是什么关系？
交往中 / 暧昧 / 分手后 / 已婚 / 其他
```

## 3. 出生时辰不明确也能使用

系统支持：

* 知道准确时间；
* 只知道大概时辰；
* 只知道上午、下午、晚上；
* 完全不知道。

出生时间不明确时，不直接拒绝，而是进入：

> **候选时辰校正**

通过少量已发生的人生事件，比较不同时辰候选盘，输出：

```text
最可能：辰时
次可能：巳时
可信度：中等
```

不宣称“绝对算出真实出生时间”。

## 4. 罗盘与真实空间环境接入

罗盘不是第十三种术法，而是空间数据采集工具。

系统可以读取：

* 手机罗盘方位；
* 手动输入坐向；
* 实体罗盘测量结果；
* 户型图；
* 大门、卧室、床、灶台、办公室位置；
* 建筑时间和入住时间；
* 周边道路、建筑、水体等环境信息。

数据提供给：

* 风水；
* 八宅；
* 玄空；
* 奇门；
* 八字喜忌辅助模块。

## 5. 支持实体测算工具

用户不必相信“AI 替我抽牌”。

可以选择：

* 系统安全随机；
* 用户自己摇铜钱；
* 实体塔罗牌录入；
* 蓍草筮法；
* 签筒和签号录入；
* 实体罗盘结果录入；
* 手动数字起卦。

AI 不参与起卦和随机，只解释固定结果。

## 6. 一事一占，避免多次结果互相冲突

同一事情、相同条件，只保留一次正式结果。

页面刷新、重复点击或网络重试：

```text
返回原结果
```

事情出现新变化：

```text
创建事件新版本
```

例如：

```text
V1：没有 offer
V2：收到口头 offer
V3：收到正式合同
```

这样结果变化是因为事情变了，而不是系统随便变了。

### Step 1：用户直接输入问题

首页主输入框：

> 你现在最想判断哪一件事？

示例：

```text
我该不该换工作？
我和他还能继续发展吗？
这套房子适不适合我住？
我今年适不适合创业？
```

### Step 2：系统识别事情类型

支持：

```text
事业
财富
感情
合盘
年度运势
短期决策
时机
搬迁
风水
学习
家庭
综合人生
```

### Step 3：最多补问两个关键问题

默认：

```text
0 个追问
```

确实缺少关键条件时：

```text
1 个追问
```

极少数复杂情况：

```text
最多 2 个追问
```

### Step 4：输入个人资料

只收集当前需要的信息：

* 出生日期；
* 出生地点；
* 性别；
* 出生时间准确程度。

### Step 5：选择测算方式

系统根据问题推荐：

```text
系统安全起卦
使用实体铜钱
实体塔罗录入
时间起卦
不使用随机起卦
```

### Step 6：多法会审

系统分别计算：

```text
个人长期基础
当前周期
短期事情
时间与方位
空间环境
现实条件
```

### Step 7：输出事情报告

重点是事情，而不是十二篇术法文章。

# 七、最小追问系统

## 设计原则

系统不应该“采访用户”，而应该只补齐判断所必需的信息。

## 实现方式

每个事件类型只定义：

* 一个最高优先问题；
* 一个备用问题；
* 信息足够时不提问。

示例：

### 事业

```text
已有明确的新机会吗？
已有 / 没有
```

### 创业

```text
准备兼职尝试还是直接全职？
兼职 / 全职
```

### 感情

```text
目前的关系状态？
交往中 / 暧昧 / 分开 / 已婚
```

### 风水

```text
你主要想看什么？
居住 / 睡眠 / 财运 / 工作 / 关系
```

## 强制规则

```text
默认 0 个
必要时 1 个
最多 2 个
```

# 八、出生时辰校正模块

## 1. 用户输入等级

```text
准确到分钟
大概时辰
上午/下午/晚上
完全不知道
```

## 2. 候选生成

完全不知道时：

```text
生成 12 个时辰候选
```

知道大概范围时：

```text
生成 2—4 个候选
```

同时处理：

* 时区；
* 夏令时；
* 出生地点；
* 真太阳时；
* 子时换日规则；
* 时辰边界误差。

## 3. 简版校时

用户选择三个历史事件：

* 升学；
* 第一份工作；
* 明显职业转折；
* 搬家或跨城市；
* 重要恋爱；
* 结婚或离婚；
* 家庭重大变化；
* 财务明显变化；
* 创业；
* 健康重大事件。

只要求填写年份，月份可选。

## 4. 候选盘比较

主要使用：

* 八字；
* 紫微；
* 西方占星；
* 吠陀占星。

输出：

```text
第一候选：辰时，匹配度较高
第二候选：巳时，匹配度中等
```

候选非常接近时，只再问一个最有区分力的问题。

## 5. 结果使用

用户可以选择：

* 使用第一候选；
* 使用第二候选；
* 同时保留两盘；
* 稍后补充资料。

如果保留两盘，报告需要显示：

```text
两盘共同结论
两盘主要分歧
出生时间不确定对结果的影响
```

# 十一、随机性系统

## 基本原则

```text
AI 不负责随机
AI 不负责抽牌
AI 不负责生成卦
```

流程：

```text
独立随机服务
→ 固定原始结果
→ 术法引擎计算
→ AI 解读
```

## 三种模式

### 1. 设备安全随机

使用：

```javascript
crypto.getRandomValues()
```

禁止使用：

```javascript
Math.random()
```

### 2. 公开可验证随机

可接公共随机信标。

记录：

* 随机来源；
* 随机轮次；
* seed hash；
* 算法版本；
* 原始结果；
* 验证指纹。

### 3. 实体输入

用户自己：

* 摇铜钱；
* 抽塔罗；
* 抽签；
* 使用实体罗盘。

系统只记录和解释。

## 算法要求

### 塔罗

```text
安全随机种子
→ Fisher-Yates 洗牌
→ 按牌阵抽取
→ 独立确定正逆位
```

### 六爻

必须保存六次三枚铜钱的原始结果，不能直接随机选择一个卦。

### 蓍草

必须按蓍草筮法对应的概率和步骤实现，不能复用铜钱概率。

# 十二、重复问事规则

## 核心规则

> **一事一档，一档一占。**

## 四种情况

| 情况      | 处理      |
| ------- | ------- |
| 页面刷新    | 返回原结果   |
| 网络重试    | 返回原结果   |
| 同一事情再次问 | 查看第一次结果 |
| 现实条件变化  | 创建事件新版本 |

## 前端按钮

已有正式测算后只显示：

```text
查看原结果
事情有了新变化
我想问另一个问题
```

不显示：

```text
再算一次
重新抽牌
换一个结果
```

## 新版本机制

```text
Case V1
├── 第一次正式测算

Case V2
├── 新条件
├── 新时间
└── 新正式测算
```

旧结果不得被覆盖。

## API 幂等

正式起卦接口必须使用：

```text
Idempotency-Key
```

避免用户双击或网络重试生成多个结果。

# 十三、综合判断与证据链

## 聚合单位

不是聚合十二篇文章，而是聚合：

> **具体判断命题**

例如创业问题拆成：

```text
长期是否适合自主发展？
未来半年时机是否成熟？
资源条件是否支持？
合伙人是否构成助力？
当前地点和环境是否有利？
立即辞职风险是否可承受？
```

每种术法只回答自己能回答的命题。

## 报告显示

```text
结论：方向可行，但当前不适合立即全职投入

支持方法：
八字、紫微、西占、吠陀

警示方法：
六爻、奇门、塔罗

现实限制：
现金储备不足
尚未验证稳定客户
```

## 时间尺度解释

报告必须区分：

```text
长期结构
当前周期
短期时机
空间环境
现实条件
```

例如：

> 长期适合创业，当前年份存在变化机会，但最近三个月的短期信号和现金储备不支持立即裸辞。

# 十四、现实条件校正引擎

这个模块不负责算命，而负责防止结果脱离现实。

检查：

* 是否已有正式合同；
* 现金储备；
* 家庭责任；
* 风险承受能力；
* 地点和通勤；
* 健康情况；
* 法律和资质限制；
* 信息完整度；
* 备选方案是否真实存在。

例如命理层输出：

```text
适合事业变化
```

现实层发现：

```text
只有两个月现金储备
新工作只有口头 offer
```

最终报告调整为：

> 适合主动寻找变化，但不建议在正式合同确认前离职。

# 二十一、最终验收标准

产品第一版正式完成时，必须满足：

1. 本期 18 法全部纳入；新建 4 法（大小六壬/铁板/雷诺曼）经文献验证+golden 通过后方计入会审；
2. 用户从具体事情开始，不从术法选择开始；
3. 默认不追问，最多追问两次；
4. 出生时辰不明确时可以继续使用；
5. 支持候选时辰校正；
6. 支持手机和实体罗盘；
7. 支持实体铜钱、塔罗等结果录入；
8. AI 不负责随机；
9. 每次正式起卦有随机来源和算法版本；
10. 同一事情只保留一次正式测算；
11. 事情变化后创建版本，不覆盖旧结果；
12. 重复测算不能增加术法权重；
13. 综合报告解释共识和分歧；
14. 报告区分长期、当前、短期、环境和现实条件；
15. 每个结论可以追溯到术法证据和规则依据；
16. 用户可以在事情结束后提交复盘；
17. 敏感内容和广告严格隔离。

# 最终竞争定位

项目真正的核心优势不再是：

```text
我们支持十二种术法。
```

而是：

> **我们围绕一件真实发生的事情，结合个人命盘、当前时间、所在地点、空间环境、实体起卦过程和现实约束，进行多法会审。**

最终品牌表达可以定为：

> **少问几句，算清一件事。**

副标题：

> **人、事、时、地、境，多法综合会审。**
