# 前端重构指示 v2 ——「一法一专页」（交本地 Agent，无代码，纯指示）

> 本文档定义**信息架构与交互重构**；视觉语言仍遵循《前端视觉重设计规范》（古籍×仪器），两份配合执行。
> 三个核心变更：① 每个术法独立专页，按各自特点定制；② 合参改为用户主动发起；③ 下架全部名人内容（法律风险）。

---

## 一、信息架构重构

### 现状问题
现在是"Cast 页多选 12 法 → Result 页 Tab 切盘面"——所有术法被压成同一张表单的复选框，丢掉了每种术数自己的仪式感和输入差异（六爻要摇卦、塔罗要选阵抽牌、风水要坐向，它们根本不该共用一张表单）。

### 新结构
```
/                      首页：术法陈列（按 命·卜·相·山 分类的入口，不是功能卡片墙）
/m/bazi  /m/ziwei  /m/qimen  /m/liuyao  /m/meihua  /m/chenggu
/m/bazhai  /m/xuankong  /m/western  /m/vedic  /m/tarot  /m/numerology
/m/hepan               合盘（双人输入，独立专页）
/heshen                合参页：用户主动把已排的盘拼起来 → /api/reading
/history  /about
```

**【硬约束】**
- 每个 `/m/{method}` 是完整闭环：本法介绍一句话 → 本法专属输入 → 本法盘面 → 本法解读。不跳转公共 Result 页。
- 出生信息全站记忆一次（本地存储），各专页自动带入，可改。换页不重填。
- 删除旧 Cast 多选页。

---

## 二、合参 = 用户主动行为

- 每个专页排完盘后，盘面角落提供一个克制的入口：**「收入合参」**（视觉上像把这张盘放进一个卷宗/匣子）。
- 顶栏有一个"卷宗"图标显示已收入几张盘；点开进 `/heshen`。
- `/heshen` 页：列出已收入的盘 → 用户输入问题 → 调 `/api/reading`（带已选 methods）→ 出合参报告（共识/分歧/三档）。
- **不再自动 12 法全跑**：`/api/reading` 的调度改为"用户收入了哪些就合哪些"；一张盘都没收时才提供"让系统推荐术法组合"的按钮（保留 selector 能力但作为建议，不是默认）。
- 合参报告里中西分歧**并陈**，沿用后端「印证 or 分歧」字段，不强合。

## 三、各专页定制规格（核心工作量）

通则：**仪式交互以"引导/建议式"为默认**——系统先给推荐（推荐牌阵、自动摇卦、当前时辰起卦），用户可切换到亲手模式。仪式动效从简（每处 ≤600ms），重点是"对味"不是炫。

### 命类（输入=生辰，重展示）
**/m/bazi 八字**
- 入口即"排盘台"：生辰录入（界格表单）→ 立即出四柱大字（干支用大号宋体，是页面主角）。
- 下方三栏：五行加权条/雷达（用 normalized.elements）、旺衰多因子结论（得令/得地/得势三枚小印，亮=得）、大运横轴。
- 子时开关、真太阳时开关放"高级"折叠区，默认收起但可见（专业用户的信任点）。

**/m/ziwei 紫微**
- 传统 4×4 去心十二宫方盘为主体；命宫朱砂细框高亮；命主/身主/五行局做盘上方题签。
- 点宫位弹出该宫主星小注（不跳页）。

### 卜类（问事驱动，重仪式）
**/m/liuyao 六爻** —— 仪式感最重的一页
- 流程：先输入**所问之事**（必填，因为用神取用靠它）→ 进入摇卦。
- 摇卦两模式，**默认"代摇"**（点一次按钮，三枚铜钱落下动画 ×6 自动连摇，3 秒内完成）；可切"亲手摇"（每爻点一次，逐爻落钱，给重度用户）。铜钱动效用正面/背面落定即可，勿做物理引擎。
- 出卦后：六爻竖排（自下而上）、装卦表（地支/六亲/六神/世应）、动爻标记、旬空月破角标、用神断语框。
- 不展示 seed/hash 等机制词——说明页讲清起卦方式即可。

**/m/meihua 梅花**
- 默认"以此刻起卦"（时间起卦，进页即排，最轻量的一法）；可改任意时刻。
- 主/互/变三卦横列，体用关系一句话总断 + 吉凶小印。

**/m/qimen 奇门**
- 问事 + 时间（默认此刻）→ 九宫式盘（3×3，按巽离坤/震中兑/艮坎乾方位排，**方位是红线不能错**）。
- 每宫叠：天地盘干、九星、八门、八神；值符值使顶部题签；格局断语（门迫/入墓/空亡）以角标落在对应宫上。
- 可加一个缓慢的"布盘"动画：九宫内容按飞泊顺序依次落定（≤1.5s 总长）。

**/m/chenggu 称骨**
- 一杆秤的视觉：年/月/日/时四个秤砣依次挂上 → 总骨重读数 → 批语以"歌诀"竖排/居中呈现。
- 全页最简，30 秒体验，适合做引流入口。

### 相/山类（空间感）
**/m/bazhai 八宅 + /m/xuankong 玄空**
- 共用**24 山罗盘选择器**组件（转盘选坐向，不用下拉）；临界角（±5°内）必须弹"建议复测"，给双候选。
- 八宅：八方罗盘图，游年星按吉（朱砂小印）/凶（墨※）落位；命卦居中。
- 玄空：九宫三数（运/山/向），格局徽标（旺山旺向等）；坐向箭头明确。
- 页面预留"上传户型图深度分析"入口（P2 平面图功能位，先放"即将推出"）。

### 西方类
**/m/western 占星**
- 圆形星盘是主角（黄道环/宫位/行星落度/相位线分色）；右侧行星表用等宽字（度数刻度感）。
- 上升/天顶轴线加粗；Placidus 宫头标度数。

**/m/vedic 吠陀**
- 北印度方形盘；行星含罗睺计都；宫内标 Rashi+Nakshatra/Pada；庙旺落陷用小标记。
- 下方 Vimshottari 大运横轴，当前大运高亮，点开看 Antardasha。

**/m/tarot 塔罗**
- 流程：输入问题 →（**默认**）系统按问题**建议牌阵**（用各阵的 `适用` 字段匹配：问感情推关系之镜、做选择推二择一、问全年推年运十二宫…），用户可改 → 洗牌动画 → **逐张点选翻牌**（翻牌是塔罗的仪式核心，保留亲手感；提供"一键全翻"给急性子）。
- 牌位按各阵传统布局（凯尔特 2 号横压 1 号、马蹄 V 形、年运环形）。
- 每张牌翻开即显牌义+正逆；全部翻完出牌组分析（大牌/逆位/花色提示）+ 解读。

**/m/numerology 数字命理**
- 极简：生日（+可选姓名）→ 生命灵数大字 + 释义卡。一屏完成。

### /m/hepan 合盘
- 双人输入并排（甲/乙两栏）；出四维档位评级（四个刻度条或四枚印，**不是百分比**）+「印证/分歧」一句话 + 关键相位与合婚要点。
- **分享卡片**：生成一张竖版图（两人属相/日柱关系/四维档位），这是裂变入口，优先做。

## 四、【法律合规】名人内容全部下架

**原因**：用真实名人的生辰排盘并公开吉凶结论，涉及——①生辰八字属个人信息（《个人信息保护法》）；②对在世真人公开"命运论断"有名誉权/人格权侵权风险（《民法典》人格权编）；③对已故名人亦可能涉近亲属权益。这类内容是同行被投诉的高发区，必须清干净。

**执行清单（前后端都要动）：**
1. 首页/任何页面删除名人案例展示与入口。
2. 后端删除 `server/data/celebrity_cases.json` 与 `GET /api/cases` 端点（或端点保留但返回空+弃用标记，前端不再调用）。
3. `BaziKline` 等组件中"名人对比"功能一并移除。
4. 替代方案：用**虚构示例**做新手引导——"示例·乾造 庚午年…"匿名样例盘 2-3 个（生辰为虚构组合，页面标注"虚构示例，仅作功能演示"）。
5. 全站自查：解读文案/prompt 模板中不得出现以真实人物为例的内容。

## 五、首页重做

- 删除名人区后，首页 = **术法陈列**：按「命（八字/紫微）· 卜（奇门/六爻/梅花/称骨）· 相（合盘/塔罗/占星/吠陀/数字）· 山（八宅/玄空）」四类竖排题签陈列，每法一行：名称 + 一句话定位 + 「适合问什么」。
- 首屏可直接展开一个最轻的体验（称骨或单张塔罗）做"开门见山"，30 秒出结果引导深入。
- 免责声明以"凡例"样式常驻页脚。

## 六、交付顺序（给 Agent）

1. 路由与 IA 改造 + 出生信息全局记忆 + 删 Cast 页。
2. **先做 3 个代表性专页定稿风格**：八字（展示型）、六爻（仪式型）、塔罗（牌阵型）→ 交样张确认。
3. 铺其余专页（紫微/奇门/梅花/称骨/八宅/玄空/西方/吠陀/数字/合盘）。
4. 合参卷宗机制 + /heshen 页 + `/api/reading` 调度改造（用户选定优先）。
5. 名人内容下架（第四节清单，**此项可与第 1 步并行立即做，不等重构**）。
6. 终验：对照《视觉重设计规范》反面清单逐条扫描 + 各盘面对位红线复核（九宫方位/爻序/牌阵布局）。

**【硬约束回顾】**：每法专页闭环不共用 Result；合参必须用户主动；仪式交互默认引导式可切亲手；盘面对位错误=打回；名人内容零残留；`blocked:true` 时不渲染任何吉凶（沿用）。
